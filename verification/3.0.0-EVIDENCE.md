## Negative controls and mutation evidence

- Before staging, `npm run gauntlet` failed immediately and listed every unstaged/untracked release path. This proved the staged-only gate was active.
- Red tests reproduced delayed-session reuse, overly broad OTP detection, delayed custom password, delayed OTP, scoped installer remediation, Playwright/app/TOTP secret leaks, HTTP fail-open, cross-target sidecars, destructive custom directories, and empty `--dir` fallback before their fixes.
- Manual mutants removed session-surface waiting, broadened OTP to generic code fields, removed custom-password waiting, removed OTP waiting, and bypassed Playwright error redaction. All five were killed by their specifically selected test; an internal TAP matcher control rejects an unrelated failing test.

## Deliberate omissions

- No npm publish and no Git tag were created; the authorized action was version bump, commit, and push.
- The user-supplied staging URL was a prompt-semantics example, so no external login was attempted and no product/domain value was added to the skill payload.
- No standalone typecheck, lint, or changed-line coverage tool exists for these plain `.mjs` helpers. Syntax checks, real-browser subprocess integration, deterministic path cases, lifecycle tests, and mutation testing cover the changed behavior instead.
- Spec approval was not obtained before implementation; the user refined the requirements during the autonomous run. Revisions 1–5 in the spec preserve those decisions for review.
